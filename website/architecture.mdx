HushMoney is a **single-user, self-hosted** deployment. One EC2 instance runs for one person.
There is no multi-tenancy, no shared infrastructure, no centralized service. You own the bot
token, the Gmail account, the EC2 instance, and the SQLite database.

## Components

### Forwarder

Python 3.12 service with two intake channels and a pattern learning subsystem:

| Module | Responsibility |
|---|---|
| `imap.py` | Polls Gmail every 5 min, parses RFC 822 messages |
| `channels/telegram.py` | Receives webhook updates from the Telegram bot (SMS forwarded by Pyrogram) |
| `sanitizer/` | Strips PII; emits `SanitizeResult` with status, redacted text, and optional `CleanPayload` |
| `sanitizer/registry.py` | Loads community YAML patterns and merges learned patterns from SQLite; hot-reloads every 2 s |
| `learning/store.py` | SQLite pattern store (`forwarder.db`) with thread-local connections and WAL mode |
| `learning/inbox.py` | Daemon thread watching `pattern-inbox/proposals/`; validates and inserts candidate patterns |
| `learning/unmatched.py` | Deduplicates and rate-limits unmatched financial notifications before forwarding to Hermes |
| `hermes.py` | HTTP POSTs `CleanPayload` to `gateway_server.py` |

The forwarder maintains its own SQLite database (`forwarder.db`) for pattern storage — separate
from Hermes's database and not accessible from the Hermes container.

### Hermes Agent

[Hermes Agent](https://hermes-agent.nousresearch.com) by NousResearch, running inside a Docker
container with an HTTP gateway server (`gateway_server.py`) that receives `CleanPayload` messages
and bank learning requests.

The agent uses **NVIDIA Nemotron 3 Nano** (`nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B`) served via
Nebius Serverless Endpoints for all LLM inference. Nemotron's MoE architecture (3B active / 30B
total) keeps latency low for frequent categorization calls while retaining quality for reasoning tasks.

### SMS Listener

`sms-listener` is a Pyrogram user client logged in as your Telegram account. It watches your
Saved Messages (self-chat) for new text matching bank notification patterns and forwards them to
the forwarder's Telegram webhook.

### Storage

| Volume | Contents | Accessible by |
|--------|----------|---------------|
| `hermes-data` | Hermes SQLite (transactions, categories, debts, settings) | Hermes only |
| `forwarder-data` | `forwarder.db` (learned patterns, fingerprints, proposals log) | Forwarder only |
| `pattern-inbox` | Proposal JSON files written by Hermes, consumed by the forwarder | Both (Hermes writes, forwarder reads/deletes) |

## Infrastructure

| Component | Details |
|---|---|
| EC2 instance | t3.small, Amazon Linux 2023, Elastic IP |
| Container runtime | Docker Compose (3 services: hermes, forwarder, sms-listener) |
| LLM inference | Nebius Serverless — no GPU on the instance |
| Database | Two SQLite databases: `hermes-data` and `forwarder-data` volumes |
| Sandbox | NVIDIA OpenShell (optional, requires kernel 6.2+) |
