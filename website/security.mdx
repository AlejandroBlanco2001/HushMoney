---
title: Security & Privacy
description: How HushMoney keeps your financial data private.
---

HushMoney is built around a single principle: **raw financial data never reaches the AI model**.
The forwarder enforces a hard sanitization boundary before anything touches Hermes.

## The privacy boundary

```
Bank notification (raw)
        │
        ▼
   Forwarder sanitizer   ← PII stripped here
        │
        ├─── matched ──────────────────────────────────┐
        │                                              ▼
        │                                    CleanPayload
        │                                    { amount, merchant,
        │                                      date, type, channel }
        │                                              │
        │                                              ▼
        │                                    Hermes Agent + Nemotron
        │
        └─── unmatched (financial only) ───────────────┐
                                                       ▼
                                             [bank_learning] header
                                             + redacted text only
                                             (no amounts, no names)
                                                       │
                                                       ▼
                                             Hermes Agent asks you
                                             to confirm expected values
```

Everything stripped before crossing the boundary:

- OTPs and verification codes
- Full account and card numbers
- Recipient names in transfers
- Phone numbers
- Any field not needed for expense tracking

## What Hermes never sees

The agent never receives and never stores:

- Raw email bodies or SMS text
- Actual amounts or merchant names from unmatched notifications
- Full account numbers (only the last 4 digits, when needed for account matching)
- OTPs or security codes
- Transfer recipient names
- Any content that could identify a third party

## Bank learning — no raw data exception

Unlike earlier versions, bank learning no longer requires Hermes to access raw content.
The forwarder sanitizes the text **before** forwarding it to the agent. What Hermes receives
for an unmatched notification is:

```
[bank_learning]
reason: no_template
channel: sms
bank: bancolombia
fingerprint: a1b2c3d4e5f6a7b8
---
Bancolombia: Transferiste $[REDACTED] desde tu cuenta *[REDACTED] a la cuenta
*[REDACTED] el [REDACTED] a las [REDACTED].
```

The agent then asks you to confirm the expected amount and date. Those values come
**only from your reply**, never from the redacted text. This means:

- No raw financial content ever reaches the model
- Proposal files store only a synthetic sample (`12345.67` / `COMERCIO PRUEBA`), not real values
- The forwarder database (`forwarder.db`) never contains actual transaction values from learning sessions

## OpenShell sandbox

When running with `--with-openshell`, the Hermes container operates under three
kernel-level enforcement layers:

| Layer | Mechanism | What it enforces |
|---|---|---|
| Filesystem | Linux Landlock | Agent can only read/write its data directory |
| Syscalls | Seccomp BPF | Blocks all system calls not on the allowlist |
| Network egress | OPA proxy | Agent can only reach Nebius API and Telegram endpoints |

The Nebius API key is managed by OpenShell and injected at the policy layer — it never
appears inside the container environment.

The `forwarder.db` volume is **not mounted** in the Hermes container — the agent cannot
read or write the pattern store directly.

## Self-hosted by design

Because this is a single-user self-hosted deployment:

- The Telegram bot token belongs to you — no third party can read your messages
- Gmail credentials are stored only in your `.env` on your EC2 instance
- The SQLite database never leaves your EC2 volume
- No financial notification content transits third-party routing services
- The Nebius API receives only clean, sanitized payloads — never raw bank data
